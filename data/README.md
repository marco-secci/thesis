# Data

## What is here

| path | in the repository | content |
|---|---|---|
| `processed/donations.parquet` | yes | the cleaned dataset: one row per donation, 2009–2025 |
| `raw/istat/eurostat_nuts3_fvg_pjanaggr3.tsv` | yes | resident population of Trieste and Gorizia, NUTS-3 (Eurostat, open data) |
| `raw/istat/eurostat_fvg_pop.json` | yes | resident population of Friuli Venezia Giulia by age group, NUTS-2 (Eurostat, open data) |
| `manifest.sha256` | yes | SHA-256 of the 27 original XLSX files the dataset was built from |
| `raw/XLSX/` | no | the original ASUGI extracts (not published) |
| `interim/`, `processed/donor_year.parquet`, `FINAL/` | no | regenerated by the pipeline |

`donations.parquet` is the output of `src/clean.py`, and every later stage of
the pipeline reads it. It is published with ASUGI's permission. The only change
from the internal version is that the full **date of birth has been reduced to
the year of birth**. Donor identifiers are pseudonymous codes assigned by ASUGI.

## `donations.parquet`: columns

353,671 rows, 43,299 distinct donors.

| column | type | meaning |
|---|---|---|
| `donor_id` | string | pseudonymous donor code (`crd` in the source files) |
| `donor_id_anag` | string | second pseudonymous code (`id_anag`); missing in 2021–2023 |
| `donation_date` | date | day of the donation |
| `donation_datetime` | datetime | day and time of the donation |
| `donation_year`, `donation_month` | int | calendar year and month of the donation |
| `donation_type` | string | type of donation as coded by ASUGI: `SANGUE` whole blood, `PLASMAF` plasmapheresis, `AFPLTPLASM`, `PLTAFE`, `AFERMUL`, `LEUCOAF` apheresis variants, `CELLSTAM`, `MIDOLESP` stem cells / marrow |
| `age` | int | donor's age in completed years on the day of the donation (18–90) |
| `birth_year` | int | donor's year of birth |
| `sex` | string | `M` / `F` |
| `donor_class` | string | administrative donor class as coded by ASUGI; its coding changes in 2016 |
| `donor_class_regime` | string | `pre2016` / `post2016`, marks that change in coding |
| `association`, `association_desc` | string | donor association (code and name); often missing |
| `collection_point` | string | collection centre (9 distinct) |
| `first_activity_date` | date | date the donor started donating, where recorded (missing for ~15% of rows) |
| `last_donation_date` | date | last donation date as reported in the yearly extract |
| `quantity_ml` | float | volume collected, in ml |
| `validity` | string | `V` valid / `N` not valid; only present in the 2023 and 2025 files |
| `is_invalid` | bool | `validity == "N"`; these rows are kept by default |
| `num_don_declared`, `quantity_total_ml` | int / float | yearly aggregates repeated on every row: control columns only. They restate the target, so they must never be used as features |
| `source_file` | string | name of the XLSX file the row came from |

To count donations, count rows; never read `num_don_declared`.
